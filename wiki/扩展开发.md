# 扩展开发

> 目标：**新增能力全程不改动已有代码** —— `/api/skills` 自动出现新 Skill，Web UI 也自动可用。

---

## 一、加一类全新能力（例：语音克隆）

五步：

```python
# 1) providers/base.py 里加接口
class VoiceCloneProvider(Provider):
    kind = "voice_clone"
    @abstractmethod
    def clone(self, *, sample_path: str, text: str, **kw) -> GenerationResult: ...
```

```python
# 2) 新建 providers/voiceclone_providers.py，实现并在 register() 中注册
def register() -> None:
    registry.register(MyVoiceCloneProvider(), default=True)
```

```python
# 3) providers/__init__.py 的 _MODULES 中加入该模块
```

```python
# 4) skills/ 加一个 @skill（声明 JSON Schema）
@skill(name="clone_voice", category="audio", is_async=True,
       description="...", input_schema={...}, output_schema={...})
def clone_voice(ctx, *, project_id, sample_asset_id, text):
    return tasks_svc.create_task(ctx.db, project_id=project_id,
                                 type="VOICE_CLONE", name="语音克隆", payload={...})
```

```python
# 5) executors/handlers.py 加 handler
@task_handler("VOICE_CLONE")
def handle_voice_clone(ctx): ...
```

完成后 `/api/skills` 自动出现新 Skill，**Web UI 也自动可用**。

> ⚠️ 记得同步在 `TaskType` 枚举里加上新类型 —— 但注意：**光加枚举不等于能用**，
> 必须有对应的 `@task_handler`。仓库里 `ADD_VOICE / ADD_MUSIC / ADD_SFX / ADD_SUBTITLE`
> 四个就是只有枚举、没有 handler 的空壳（实际生效 16 个）。

## 二、换一个生图 / 生视频模型

**优先用工作流模板机制** —— 不需要改代码：

1. 在 ComfyUI 中导出 **API Format** 工作流 JSON（Workflow → Export (API)）
2. 把可变字段替换成占位符：

```json
{ "6": { "inputs": { "text": "{{prompt}}", "seed": "{{seed}}" } },
  "5": { "inputs": { "width": "{{width}}", "height": "{{height}}" } } }
```

3. 丢进 `backend/app/workflows/templates/`，或放外部目录并在 `.env` 设 `COMFYUI_WORKFLOW_DIR`
4. 调用时带 `workflow_name`

支持占位符：`{{prompt}} / {{negative_prompt}} / {{width}} / {{height}} / {{seed}} / {{image}} / {{frames}}`

> **类型保留规则**：当某个值**整个字符串**就是 `{{key}}` 时，替换后保留原始类型；
> 若内嵌在长字符串里，则做文本替换、结果为字符串。这解决了 ComfyUI 对
> `width` / `seed` 必须为数字的硬要求。

详见 [模型引擎与配置](模型引擎与配置#五接入-comfyui出图--图生视频)。

### 也可以直接传 workflow_json

```bash
agent_cli.py call generate_video '{"shot_id":"shot_03","provider":"comfyui",
     "parameters":{"workflow_json":{...},"ckpt_name":"wan2.1.safetensors"}}'
```

Provider 会自动完成 `POST /prompt` → 轮询 `/history/{id}` → 下载 `/view`，
并把 `prompt_id`、工作流名、模型名一并写入 Asset 元数据（可追溯）。

## 三、接入新的 Agent

Skill 层是纯 HTTP + JSON Schema，任何能发请求的 Agent 都能用：

- **通用 LLM Agent**：把 `/api/skills?detail=true` 的结果塞进 system prompt（工具定义），
  用 function calling 直接映射到 `POST /api/skills/{name}/invoke`
- **传统工作流引擎**：把 `invoke` 当作 HTTP 节点
- **自研脚本**：直接用 `agent_cli.py`

不需要改本工程任何代码。

## 四、切换存储后端

## 五、扩展时必须守住的约束

### 分层不能反向依赖

```
L1 Agent → L2 Skill → L3 Executor → L4 Provider → L5 Engine
```

- `providers/` **不 import** `skills/`
- `executors/` **不 import** 具体 Provider 实现，只通过 `registry.get(kind, name)`

这条约束不是洁癖 —— 它是[模型可换](核心概念#03--模型是可替换的零件)能成立的前提。一旦执行层 import 了某个具体 Provider，换模型就得改执行层。

### 写路径只动本集

涉及连续剧时，**读用「池」（`character_pool`），写只动「本集」（`own_characters`）**。
否则一次回退会把整个系列的主角形象清掉。详见 [连续剧与角色](连续剧与角色#一条必须守住的边界读用池写只动本集)。

### 上游一变，下游一律失效

新增流水线节点时，必须在 `core/constants.py::STAGE_DOWNSTREAM` 里登记它的下游，
否则会出现"上游换了、下游还是旧的"脏状态。详见 [生产流水线](生产流水线#下游失效矩阵最关键的设计)。

### 新增表列走轻量迁移

不要手工改库。在 `database.py` 的对应集合里登记，启动时自动对齐：

| 集合 | 用途 |
|---|---|
| `_ADDED_COLUMNS` | 补列 |
| `_DROP_NOT_NULL` | 解除 NOT NULL |
| `_ADDED_FOREIGN_KEYS` | 补外键 |

### 前端新增 MUI 图标要登记

`vite.config.js` 里维护了 MUI 图标的预构建白名单（`MUI_ICONS`）。
**新增图标时必须同步登记**，否则首次引用会触发重新预构建，撞上开发机的 safe-delete 保护，dev server 当场退出。

## 六、已知边界

| 项 | 现状 | 方向 |
|---|---|---|
| 人物一致性 / 伪影检测 | 需 VLM，当前固定 `WARN` 并声明 `requires: vision_model` | 接入视觉质检 provider |
| Face Enhancement | 算子已定义，未接模型时 `skipped` | 接入 GFPGAN / CodeFormer |
| 转场 / 精细剪辑 | 仅拼接与基础处理 | `EDIT_VIDEO` 增加 xfade 与时间线 DSL |
| `ADD_*` 任务类型 | 4 个只有枚举、无 handler | 实现或从枚举中移除 |
| 认证与多租户 | 单机单用户 | API Key 中间件 + `owner` 过滤 |
| 成本与配额 | 未统计 | 在 `tasks.result` 记录耗时与算力消耗，做预算护栏 |
