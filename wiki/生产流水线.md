# 生产流水线

> 把「生产进度」从一根进度条升级为**可交互的节点图**，并新增节点级回退、审核、重生成。
> 完整版见 [docs/PIPELINE_NODES.md](https://github.com/fatman1221/video-genrate/blob/main/docs/PIPELINE_NODES.md)。

---

## 一、为什么是节点而不是进度条

一根进度条只能**看**，不能**动**。用户看到某一步不满意，只能整项目重跑。

而视频生产本质是**试错过程**：第 5 步的配音不对、第 3 个镜头的人物不符，都是常态。所以要的是：

1. 生产进度是**节点**，不是一个百分比数字
2. 节点**可交互**：点进去看产出、回退、重生成、审核通过或驳回
3. 视觉简约，用缩略图 / 图标 / 环形进度表达信息，不靠文字堆砌

---

## 二、12 个节点

```
脚本 → 分镜 → 人物 → 画面 → 镜头视频 → 配音 → 配乐 → 字幕
     → 画质增强 → 剪辑 → 合成 → 质检
```

| 节点 | 标签 | 图标语义 | 可审核 |
|---|---|---|---|
| `script` | 脚本生成 | 文档 | ✓ |
| `storyboard` | 分镜拆解 | 网格 | ✓ |
| `character` | 人物设定 | 面部 | ✓ |
| `image` | 画面生成 | 图片 | ✓ |
| `video` | 镜头视频 | 胶片 | ✓ |
| `voice` | 配音生成 | 麦克风 | ✓ |
| `music` | 配乐生成 | 音符 | ✓ |
| `subtitle` | 字幕生成 | 字幕条 | ✓ |
| `enhancement` | 画质增强 | 闪光 | — |
| `editing` | 剪辑 | 剪刀 | — |
| `composing` | 合成 | 滤镜 | ✓ |
| `quality_check` | 质量检查 | 盾牌 | — |

节点视觉：已完成=紫 · 进行中=实心紫+脉冲 · 失败=红 · 待执行=灰虚线。
右上角审核徽章：✓ 通过 / ! 驳回。连接线：前置已完成=紫实线，否则灰虚线。

## 三、回退 / 重生成 / 审核

| 能力 | 语义 |
|---|---|
| `node_view` | 12 个节点的完整视图：状态、真实产出比例、产出缩略图、审核结论、可执行动作 |
| `rollback_to` | 回退到某节点：该节点 + 全部下游重置为 `PENDING`；下游产物引用清空（**文件保留**） |
| `regenerate_stage` | 只重跑某一个节点；默认先清空该节点产物再全量重跑，也可"只补缺" |
| `review_stage` | 审核通过 / 驳回；驳回可选自动回退 + 立即重跑 |

### 下游失效矩阵（最关键的设计）

**上游一变 ⇒ 下游一律失效。** 定义在 `core/constants.py::STAGE_DOWNSTREAM`：

| 变更的节点 | 随之失效的下游 |
|---|---|
| `script` | storyboard / character / image / video / voice / music / subtitle / enhancement / editing / composing / quality_check |
| `storyboard` | image / video / voice / subtitle / enhancement / editing / composing / quality_check |
| `character` | image / video / enhancement / editing / composing / quality_check |
| `image` | video / enhancement / editing / composing / quality_check |
| `video` | enhancement / editing / composing / quality_check |
| `voice` | composing / quality_check |
| `music` | composing / quality_check |
| `subtitle` | composing / quality_check |
| `enhancement` | editing / composing / quality_check |
| `editing` | composing / quality_check |
| `composing` | quality_check |
| `quality_check` | — |

**为什么必须这样**：否则会出现"画面换了、视频还是旧的"这种**脏状态** —— 而这种状态在有 Agent 参与的自动化流程里几乎必然发生。与其靠 Prompt 提醒它，不如让系统在结构上不可能出错。

### 状态与审核解耦

生产状态（`state`）与审核状态（`review_status`）是两条独立的线：

- 一个节点可以「已生产完成但尚未审核」
- 也可以「被驳回后重新生产」
- **驳回结论在回退之后依然保留** —— 记录的是判断，不是进度

`workflow_steps` 相关列：`review_status` / `reviewed_by` / `reviewed_at` / `review_comment` / `rolled_back_at` / `rollback_count`。

## 四、Skill 与 REST

| Skill | 异步 | 说明 |
|---|---|---|
| `get_pipeline` | 否 | 读节点视图 |
| `rollback_stage` | 否 | 回退 |
| `regenerate_stage` | 是 | 重生成，返回 `taskId` |
| `review_stage` | 否 | 审核 |

REST：`GET /api/projects/{id}/pipeline` —— 节点图数据源（前端 3 秒轮询）。

## 五、Web UI

### 节点操作面板（右侧抽屉）

- **产出**：缩略图墙（视频用所属镜头关键帧当封面，点击可播放）
- **元信息**：耗时 / 尝试次数 / 更新时间
- **审核**：意见输入 + 审核通过 / 驳回（驳回二次确认，可一并回退重做）
- **重新生成**：「全量重跑 / 只补缺」开关 + 一键重跑
- **回退**：二次确认后回到该节点重来

### 信息架构

13 个文字标签页 → 8 个：**概览 / 脚本 / 分镜 / 人物 / 素材 / 配音 / 任务 / 日志 / 成片**。
素材页内部用 ToggleButton 过滤类型，不再为每种素材单开标签。

## 六、实测记录

### 回退

```
POST /api/skills/rollback_stage/invoke
{"project_id":"proj_5af2...","step_key":"subtitle","reason":"人工审核：字幕断句需要调整"}
→ 重置节点: [subtitle, composing, quality_check]
→ 清空产物: {subtitle: 4}          # 4 个镜头的字幕引用被清空
→ 工作流状态: MUSIC_GENERATED      # 回退到上一个节点已完成的状态
→ 进度: 84% → 80%
```

### 重新生成

```
POST /api/skills/regenerate_stage/invoke
{"project_id":"proj_5af2...","step_key":"subtitle","reset":true}
→ 提交任务: 1 个（GENERATE_SUBTITLE）
→ 12 秒后：字幕节点 SUCCESS 4/4，工作流自愈到 SUBTITLE_GENERATED
```

### 审核

```
审核通过：{"step_key":"script","decision":"APPROVED","comment":"脚本结构清晰，可用"}
→ review_status=APPROVED, reviewed_by=human

驳回并回退：{"step_key":"music","decision":"REJECTED","comment":"配乐情绪与教学基调不符",
            "auto_rollback":true}
→ review_status=REJECTED（结论在回退后仍然保留）
→ 重置节点: [music, composing, quality_check]
→ 工作流: VOICE_GENERATED，进度 100% → 80%
→ 节点图：脚本生成显示 ✓ 徽章，配乐生成显示 ! 徽章
```

## 七、已知限制

- 审核结论暂无独立的角色权限体系（`actor` 由 `?actor=` 查询参数决定，Web UI 记为 `human`）
- `node_view` 每次会聚合缩略图，节点较多时建议加缓存（当前 12 节点开销可忽略）
- 「人物一致性」类质检项仍需接入 VLM 才能给出确定结论，目前固定为 `WARN`
