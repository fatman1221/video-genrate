# 连续剧与角色

> 一句话：**一部剧 → 多集 → 每集一条完整流水线**。
> 完整版见 [docs/SERIES.md](https://github.com/fatman1221/video-genrate/blob/main/docs/SERIES.md)。

---

## 一、为什么需要这一层

最初的模型里，一个 `Project` 就是一条完整流水线。`Project.scripts` 虽然是一对多，但语义是「同一份剧本的多个版本」（带 `version` 字段），且 `Storyboard / Scene / Shot` 全部只挂 `project_id`、**与脚本没有任何关联**。

这意味着：往同一个项目里塞三个脚本（第 1/2/3 集）会出问题 ——

- 三个脚本都躺在库里，但 `get_script(project_id)` 只取最新的一份
- 三集的分镜、镜头混在同一条流水线里，`Shot` 无法区分归属
- 最终只能合成出**一个**成片文件

**「脚本多个」是内容层的事，「连续剧」是结构层的事** —— 光让脚本变多个解决不了。

---

## 二、分层结构

```
Series（一部连续剧）
  ├── Character（系列级角色库，跨集复用）
  └── Project（第 1 集）        ← 一集就是一个普通 Project
  │     └── Workflow → Script / Storyboard / Scene / Shot / Asset / Task
  ├── Project（第 2 集）
  │     └── 独立的 Workflow …
  └── Project（第 N 集）
```

### 关键取舍：为什么「一集 = 一个 Project」

另一种做法是新增 `episodes` 表，让 `Script / Storyboard / Shot / Workflow` 全部加 `episode_id`。那样结构更内聚，但代价很大：需要数据迁移，且**节点回退、审核、重生成、进度统计全部要按集重写一遍**。

而把一集建模成 Project 则**零成本复用**已经验证过的整套能力：

- 每集有独立的 `Workflow` 与节点状态
- 每一集的「点节点回退 / 重新生成 / 审核」互不干扰
- 某一集崩了不会污染其它集
- 每集独立产出成片，符合连续剧一集一集发布的形态

代价只是心智上的：**Project 在这里的含义是「一集」**。UI 上直接显示成「第 N 集」，`Project.series_id` 为空时才当作独立项目。

## 三、数据模型变更

| 表 | 变更 | 说明 |
|---|---|---|
| `series` | **新增** | 剧名、总需求、风格、每集时长、计划集数、画幅/帧率 |
| `projects` | `series_id` | 所属系列，`ON DELETE SET NULL`（删剧不解散集） |
| `projects` | `episode_no` | 集号，从 1 开始；0 表示独立项目 |
| `characters` | `series_id` | 系列级角色标识，`ON DELETE CASCADE` |
| `characters` | `project_id` 改为**可空** | 系列级角色不隶属任何一集 |

自动迁移在 `database.py::init_db()` 中完成（补列 → 解除 NOT NULL → 补外键），老库无需手工干预，启动即对齐。

## 四、角色跨集复用（连续剧的核心）

`Character` 有两种归属：

- **本集角色**：`project_id` 有值 —— 只属于这一集
- **系列级角色**：`series_id` 有值、`project_id` 为空 —— 全系列共享

主角应该建在系列层，否则每集都要重造一遍角色，形象必然漂移（**换集换脸**）。

### 一条必须守住的边界：读用「池」，写只动「本集」

`services/characters.py` 提供两个入口：

| 函数 | 范围 | 用途 |
|---|---|---|
| `character_pool(db, project)` | 本集角色 **+** 所属系列的系列级角色 | 分镜引用解析、planner 角色分配、界面展示、节点统计 |
| `own_characters(db, project_id)` | **仅本集自有角色** | 重置、清空引用等**写操作** |

**为什么必须分清**：系列级角色的参考图由全系列共享。如果某一集执行「回退 / 重生成人物设定」时把它一并清空，第 2、3 集的主角形象会跟着一起废掉。

因此：

- `pipeline.rollback_to(stage="character")` **只清本集角色**
- `pipeline.regenerate_stage(stage="character")` 对系列级角色**只在缺图时补齐**，不重置

## 五、Skill 与 REST

### Skill（`category="series"`，11 个）

| Skill | 作用 |
|---|---|
| `create_series` | 建剧；`episodes=N` 可顺便开好前 N 集 |
| `list_series` / `get_series` / `update_series` / `delete_series` | 剧的管理 |
| `create_episode` | 新建一集（自动继承系列风格/画幅/时长，集号自增） |
| `list_episodes` | 列出各集及进度 |
| `attach_project_to_series` / `detach_project_from_series` | 把已有项目收编为集 / 摘出为独立项目 |
| `list_series_characters` | 系列角色库 |
| `promote_character_to_series` | 把某集角色提升为系列级 |

> `delete_series` 默认只**解散**系列（各集降级为独立项目、数据保留）；
> 传 `delete_episodes=true` 才会连同每集的素材、镜头、任务一并彻底删除。

### REST

```
GET    /api/series                      列表（含总进度、集数、封面）
POST   /api/series                      建剧
GET    /api/series/{id}                 详情（含各集摘要 + 系列角色）
PATCH  /api/series/{id}                 更新
DELETE /api/series/{id}?delete_episodes= 删除
GET    /api/series/{id}/episodes        各集
POST   /api/series/{id}/episodes        新建一集
GET    /api/series/{id}/characters      系列角色库
```

## 六、典型流程（Agent 视角）

```
create_series(name="AI Agent 从入门到实战", episode_duration=300,
              planned_episodes=12, episodes=3)
  ↓
create_character(series_id=..., name="阿智", role="protagonist")   # 建在系列层
  ↓
create_episode(series_id=..., requirement="第 1 集：讲清 Agent 与脚本的区别")
  ↓
create_script(project_id=ep1) → create_storyboard(project_id=ep1)
     # 分镜会自动引用系列级角色「阿智」（走 character_pool）
  ↓
run_pipeline(project_id=ep1) …／逐节点推进、回退、审核
  ↓
compose_video(project_id=ep1)                                       # 第 1 集成片
```

第 2 集重复 `create_episode → …` 即可，**主角形象自动复用**。

## 七、实测结论

- 系列 1 部 / 3 集 / 系列级角色「阿智」1 个
- 第 1、2 集各自生成 8 场景 48 镜头，**48/48 全部自动引用系列级角色**
- 两集工作流状态彼此独立（22% / 22% / 0%），镜头互不冲突
- 手工用中文名 `"阿智"` 引用镜头角色，能正确解析为角色 id
