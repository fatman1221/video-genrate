核心原则

能力全部抽象成 Skill，业务逻辑不写死在 Prompt 里

每条原则都有明确的落地位置，不是口号。

01
契约先行每个 Skill 都有 JSON Schema 输入输出、状态与错误码，调用前可自省。
02
长任务异步化生成类调用立即返回 taskId，Agent 轮询即可，绝不阻塞。
03
最小粒度重跑单个镜头失败只重跑那个镜头，不整项目重来。
04
可追溯每个产物记录 Prompt / 模型 / 参数 / Provider / 工作流。
05
失败恢复指数退避重试 + 孤儿任务回收 + 断点续跑。
06
优先级 API > CLI > 浏览器浏览器自动化只做任务登记，实际执行交给 Agent。
07
可换模型Provider 注册表运行时切换，业务层零改动。
08
上游变则下游失效画面重做后，视频 / 剪辑 / 合成 / 质检自动重置，杜绝脏状态。
生产流水线

进度不是百分比，是一张可交互的节点图

点开任意节点即可查看产出、回退到该步、重新生成该步、审核通过或驳回。

回退到该步

该节点与全部下游重置为待执行，后续产物引用清空（文件保留）。取消半新半旧的中间态。

重新生成该步

只重跑一个节点，支持「全量重跑」与「只补缺」两种策略，完成后自动向前推进。

审核通过 / 驳回

生产状态与审核状态解耦：可以「已生产但未审核」，也可以「驳回并一键回退重做」。

连续剧分层

一部剧 → 多集 → 每集一条完整流水线

一集即一个项目，所以每集的回退、审核、重生成、成片全部复用现成能力；主角建在系列层，跨集不换脸。

Series 一部连续剧：剧名、总需求、风格、每集时长、计划集数

快速开始

三条命令起来，Agent 三步接入

启动后端 / 前端
# 后端（FastAPI + PostgreSQL）
cd backend
env -u PYTHONPATH python -m uvicorn app.main:app \
    --host 127.0.0.1 --port 8077

# 前端（React + Vite + MUI）
cd frontend
npm run dev      # http://127.0.0.1:5180

# 一键端到端验收
env -u PYTHONPATH python scripts/e2e_check.py 20 5
Agent 接入三步
# 1) 看清单：平台有什么能力
agent_cli.py skills --category video

# 2) 看契约：输入输出是什么
agent_cli.py describe generate_video

# 3) 调用：异步，立即返回 taskId
agent_cli.py call bootstrap_project \
  '{"name":"…","target_duration":300}'

# 推进并盯住流水线
agent_cli.py pipeline proj_xxxxx --watch
GET/api/skillsSkill 清单与契约

GET/api/projects/{id}/pipeline节点流水线数据源
GET/api/series/{id}连续剧详情与分集
